---

## コンフリクトとは？

コンフリクトは、**同じファイルの同じ部分を複数人が編集したとき** に起きます。

Git は「どちらの変更を採用すべきか」を自動で判断できないため、手動で解決する必要があります。

### 例

```
Aさん: README.md の 3行目を「Hello」に変更
Bさん: README.md の 3行目を「こんにちは」に変更

→ Git: 「どっちを採用すればいいの？」→ コンフリクト発生！
```

> **今回の演習では**: 各自が別々のファイルを作るのでコンフリクトは起きにくいですが、
> 実際のチーム開発ではよく遭遇します。対処法を知っておきましょう。

---

## コンフリクトが起きたときの表示

コンフリクトが発生すると、ファイルの中にこのような印が付きます:

```
<<<<<<< HEAD
自分の変更内容
=======
相手の変更内容
>>>>>>> feature/other-branch
```

| 記号 | 意味 |
|------|------|
| `<<<<<<< HEAD` | 自分の変更の開始 |
| `=======` | 自分の変更と相手の変更の区切り |
| `>>>>>>> ブランチ名` | 相手の変更の終了 |

---

## コンフリクトの解消手順

### 1. コンフリクトの発生を確認

```bash
git pull origin main
```

コンフリクトがあると以下のように表示されます:

```
Auto-merging ファイル名
CONFLICT (content): Merge conflict in ファイル名
Automatic merge failed; fix conflicts and then commit the result.
```

### 2. ファイルを編集して解消

コンフリクトが起きたファイルを開いて、以下を行います:

**Before（コンフリクト状態）:**
```
<<<<<<< HEAD
- Python
- JavaScript
=======
- Python
- TypeScript
>>>>>>> main
```

**After（解消後）:**
```
- Python
- JavaScript
- TypeScript
```

`<<<<<<<`、`=======`、`>>>>>>>` の印をすべて削除し、最終的に残したい内容だけにします。

### 3. 解消したファイルをコミット

```bash
git add ファイル名
git commit -m "fix: コンフリクトを解消"
```

---

## コンフリクトを避けるコツ

| コツ | 説明 |
|------|------|
| **こまめに pull する** | 最新の変更を取り込んでおく |
| **小さな変更を頻繁にコミット** | 大きな変更ほどコンフリクトしやすい |
| **チームで作業範囲を分ける** | 同じファイルを同時に編集しない |
| **作業前に声をかける** | 「このファイル触りますよ」と伝える |
